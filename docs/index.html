THESIS / 一句话定位

导梦是一个面向非专业短视频与短剧创作者的 AI 视频创作工作流：把「一句话灵感」变成一条可确认、可修改、可继续生成的视频生产流水线。

它不是又一个「文生视频黑盒」，而是一条覆盖剧本、角色、分镜、参考图、视频、后期的完整生产链；每个关键节点都让用户查看、确认和修改。

非专业创作者表达门槛生成可控性结构化创作流程多阶段确认低成本试错角色一致性分镜驱动首轮可用率模型能力边界

FRAME / 面试表达框架

  • 01 背景AI 视频工具很多，但创作过程分散、黑盒、难修改。
  • 02 用户问题非专业用户有创意，却缺少编剧、分镜和导演能力。
  • 03 产品方案把创作拆成六阶段，每阶段可确认、可修改、可继续。
  • 04 我的职责AI 产品经理：需求分析、工作流拆解、剧本 Agent 设计、MVP 落地。
  • 05 结果指标剧本一次可用率约 45%→72%，分镜可承接率约 50%→76%。

用户从创意到成片，每一步都在「抽卡」

痛点不是「不会写提示词」这一件事，而是贯穿创意到成片的整个链路。按用户旅程来讲，面试官更容易听懂。

USER JOURNEY PAIN
01创意构思

用户只有粗糙想法，不知道怎么变成完整故事：主角是谁、冲突是什么、剧情怎么推进。

剧本阶段把模糊创意扩展成结构化短剧。
02剧本结构

不知道如何控制节奏、镜头数量、人物对白和情绪转折，一句话生成方向不稳定。

剧本 Agent 补全场景、人物、风格、动作与镜头表达。
03角色与场景

没有统一资产设定，每次生成都像重新抽卡：脸变了、衣服变了、场景风格也变了。

角色与场景 Agent 沉淀固定视觉资产，供后续镜头复用。
04分镜设计

不会拆镜头，动作描述模糊，图生视频时动作不合理、镜头不连贯。

分镜 Agent 拆出景别、动作、时长与画面重点。
05参考图与视频

成本最高、最容易抽卡；多次生成后人物、场景、剧情难以保持一致。

参考图 Agent + 首帧/首尾帧/参考图三种生成模式。
06后期拼接

多段视频时长有限，拼接后一致性差，还要处理字幕、配音、剪辑与成片节奏。

后期 Agent 按分集与 segment 顺序拼接成片。
导梦的机会点

不直接替用户「一句话生成视频」，而是把创作流程拆成多个可确认的阶段。把错误提前暴露在低成本阶段，减少后期高成本抽卡，提高角色一致性与成片可控性。

一句话灵感，经过六次明确交接

每个 Agent 只解决一个阶段问题。用户确认当前产物后，WorkflowEngine 才把确定版本交给下游。

面试常问：项目最大的难点是什么

准备两到三个真实难点，每个难点按「表现 → 定位 → 解决 → 结果」讲述，并落到可迁移的方法。

PROBLEM-SOLVING
DIFFICULTY 01 · 信息断裂

剧本、角色、分镜、视频之间信息断裂

阶段各自独立生成，中间产物缺少结构化字段承接，导致角色不一致、分镜承接率低、跨环节信息丢失。

定位：不是模型单点问题，而是链路缺少结构化中间资产与确认点。

解决：结构化字段 + 用户确认 + 局部重生成，同一 segment_id 贯穿分镜、参考图与视频。

结果：分镜可承接率约 50% → 76%。
DIFFICULTY 02 · 一次可用率

剧本首次生成可用率只有约 45%

用户输入模糊，提示词自动补全的信息不稳定，模型对「人物、场景、风格、冲突」的理解宽泛。

定位：通过三轮提示词评测定位到信息缺口与字段缺失。

解决：结构化字段优化 + 失败回退机制，把关键缺口交给用户确认。

结果：剧本一次可用率约 45% → 72%。
DIFFICULTY 03 · 生成不可控

黑盒生成导致反复抽卡、成本浪费

一句话直接出片时，局部不满意只能整条重来，token 与生成额度浪费严重。

解决：多阶段确认把错误拦截在低成本阶段；参考图约束画面；支持首帧/首尾帧/参考图三种模式。

方法：让用户在最终结果之前确认，而不只是在成片上承担失败成本。
DIFFICULTY 04 · 评测前置

评测标准如何成为产品控制机制

借鉴模型评测思路：先定义不同分值对应的状态与阈值，再用这些边界约束模型生成。

解决：Rubric 与阈值约束生成过程，确定性边界交给状态、规则和代码。

方法：AI 稳定性不能只依赖提示词，要把安全边界与数值交给程序控制。
沉淀的方法

第一，AI 产品稳定性不能只依赖提示词，要把确定性边界交给状态、规则和代码；第二，评测方法可以前置为产品控制机制；第三，排查 AI 问题必须覆盖整条调用链，并保留版本记录与回归用例。

CONCEPT + PROJECT EVIDENCE

Agent 架构

AGENT = MODEL + HARNESS

Agent 能围绕目标自主完成任务：理解目标、拆解任务、调用工具、观察结果、继续调整。一般分交互层、理解与决策层、规划层、记忆与上下文层、工具执行层、运行与控制层。

导梦是集中式六阶段 Agent 工作流：WorkflowEngine 是运行控制中枢，Session 是记忆与状态，各阶段 Agent 是执行单元。

Workflow vs Agent

FIXED PIPELINE vs AUTONOMOUS LOOP

Workflow 是固定编排，路径确定、可预期；Agent 是动态决策，根据中间结果选择下一步。适合确定性任务用 Workflow，开放任务用 Agent。

导梦核心链路是 Workflow（六阶段固定顺序），每个阶段内部用模型做开放生成；这是「Workflow 为主 + 模型决策」的组合。

Harness vs Hermes

MECHANISM vs FRAMEWORK

Harness 是通用 Agent 运行机制：接收指令、调用工具、管理上下文、保存状态、失败重试、判断完成。Hermes 是具体开源 Agent 框架，内部封装了一套 Harness。

导梦没有直接基于 Hermes 开发，而是自建 Workflow 与 Harness 机制：模型、状态、工具、记忆、运行控制都由自己的前后端实现。

ReAct

REASON + ACT LOOP

模型在推理与行动之间交替：先思考当前需要什么信息，再调用工具获取，观察结果后继续推理，直到完成任务。

导梦的局部重生成与失败回退可以类比：Agent 根据上一阶段产物判断缺口，再决定是否重做目标资产。

MCP

MODEL CONTEXT PROTOCOL

标准化模型接入外部工具与数据的协议，让 Agent 用统一方式调用搜索、文件、数据库、API 等能力。

导梦通过模型适配层（LLM/Image/Video Adapter）屏蔽不同服务商调用差异，思路与 MCP 一致：业务不绑定单一厂商。

Skill

REUSABLE CAPABILITY

把一套任务流程封装成可复用能力，有明确触发条件、输入输出、工作步骤、事实约束与测试方式。

面试复盘 Skill：把「提取原问题 → 诊断回答 → 映射项目 → 可编辑确认 → 写入飞书」沉淀成可复用流程，正是 Skill 的实践。

FDE

FORWARD DEPLOYED ENGINEER

深入真实业务现场，把模型和平台能力转化成生产环境可运行的系统：理解工作流、找到 AI 改造点、最小方案、生产化、推广与沉淀。

政府采购规则 Agent 是一次小规模 FDE 式实践：把规则文档作为知识源，保留引用与人工确认。

AI Native

AI AS CORE VALUE

AI 不是附加功能，而是产品核心价值与交互方式的来源。导梦用模型能力重组「视频创作」这件事本身。

导梦的六阶段生成链、局部重生成、结构化中间资产，都是围绕模型能力边界设计的 AI Native 产品。

HIGH-FREQUENCY Q&A
  1. Q1请做一个简短的自我介绍
    框架：一句话定位（两段 AI 实践）+ 两个可验证能力（模型评测判断力、AI 产品 0→1 落地）+ 一个项目钩子（导梦/饲界）。不要罗列所有经历。
  2. Q2请完整介绍导梦这个项目
    框架：背景 → 用户问题 → 产品方案（六阶段工作流）→ 我的职责（剧本 Agent 设计）→ 结果指标（一次可用率 45%→72%）。强调「可确认、可修改、可继续生成」而非单纯 prompt 工具。
  3. Q3你在项目中的角色、职责和团队分工是什么
    要点：产品设计与 AI 生成链路优化；区分个人负责（剧本 Agent 输入输出/确认/回退）与团队协作（后端、模型接入、其他 Agent 联调）；明确技术边界。
  4. Q4项目最大的难点是什么，你如何定位并解决
    要点：选「信息断裂」或「一次可用率低」，按「表现 → 定位 → 解决 → 结果」讲；落脚到可迁移方法（结构化字段、评测前置、局部重生成）。
  5. Q5你的产品与竞品有什么差异
    要点：区分直接竞品与间接竞品；导梦对比即梦等：不只生成，而是可确认、可修改、可继续生成的全链路工作流；「功能只是手段，用户价值才是差异」。
  6. Q6为什么拆成多个阶段，而不是一句话直接生成视频
    要点：一句话生成对当前模型不可控、试错成本高；拆阶段把错误拦截在低成本阶段，提高角色一致性与成片可控性；未来模型变强可加「一句话快速模式」。
  7. Q7如果导梦上线后用户反馈「生成结果不稳定」，你怎么定位
    要点：先拆类型（理解偏差/视觉一致性/动作镜头/画质/流程体验），再按链路逐层排查（输入→剧本→角色→分镜→参考图→视频），用阶段重生成率定位问题环节，最后前移确认点。
  8. Q8如何为导梦设计核心指标体系
    要点：北极星「有效成片率」；过程看阶段完成率与漏斗流失；交互看各阶段重新生成率、确认率、修改次数；成本看单条成片平均生成次数与 token；结果看首轮可用率、导出率、复用率、留存。
使用建议：凡涉及具体数字、公司名称、上线状态、模型名称和项目结果，都以你的真实记录为准，不要为了答案完整而补造信息。
